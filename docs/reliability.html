Сохранение и обновление

Редактор сохраняет исходник по вашей команде, а копии для восстановления ведёт отдельно.

Обычное сохранение

Ctrl+S записывает новый текст во временный файл рядом со сценой, сбрасывает запись на диск и заменяет исходник. Если запись или замена не удалась, исходник остаётся прежним. Ошибка показывается в строке состояния. Перед заменой предыдущий текст сохраняется в .motif-history/имя-сцены.msc/; хранятся десять последних версий.

Если другой редактор изменил или удалил исходник, Motif откажется затирать его вашими правками. «Сохранить как…» под новым именем позволяет оставить обе версии. Окно закрытия также спрашивает, что сделать с несохранёнными правками.

После сбоя

Каждые пять секунд редактор записывает изменённый документ в %LOCALAPPDATA%\Motif\recovery (Linux: $XDG_STATE_HOME/Motif/recovery или ~/.local/state/Motif/recovery). Сохраняется текст всех холстов, настройки Web-экспорта и незаконченный скрипт, даже если он пока не разбирается. У разных окон отдельные копии.

При следующем запуске появляется список доступных копий. Его также можно открыть через «Файл → Восстановление документов…». Кнопка «Восстановить» загружает текст в редактор: проверьте его и сохраните. Исходный файл до этого не меняется. Если исходник после сбоя изменился, сохраняйте восстановленный вариант под другим именем.

Восстановленная копия становится копией текущего окна: если редактор снова упадёт до сохранения, она не потеряется, а прежний файл копии удаляется. Ненужную копию убирает кнопка «Удалить» (после «Точно удалить»), а если копий несколько — «Удалить все копии». Копии окон, которые ещё открыты, второе окно Motif не предлагает: они принадлежат своему окну.

«Файл → Предыдущие сохранения…» открывает список версий из .motif-history, от новой к старой, с просмотром начала текста. Восстановление любой версии можно отменить через Undo.

Автокопии не заменяют резервное копирование диска: при аварии можно потерять правки с последнего пятисекундного интервала, а картинки и шрифты из внешних файлов в автокопию не входят. Размер одной JSON-копии ограничен 64 МиБ; при превышении редактор просит сохранить документ вручную. Если папка недоступна, редактор сообщает об ошибке. Аварийные копии хранятся, пока их не восстановят или не удалят; копии, уже совпадающие с исходником, скрываются из списка.

Обновление одной командой

  1. Сохраните сцены и закройте Motif из обновляемой папки.
  2. Запустите update.bat. Установка Rust или ручная сборка не нужна.
  3. После сообщения Motif updated запустите редактор.

Обновлятор получает Windows-сборку из GitHub Releases, сверяет SHA-256 каждого файла с манифестом пакета и проверяет совпадение версий программы и Godot-аддона. Затем резервирует заменяемые файлы. При ошибке копирования откатывает уже заменённые компоненты. Если процесс оборвался, следующий запуск BAT сначала восстанавливает предыдущую установку по журналу .motif-update.

Пользовательские файлы не удаляются. В examples и godot-apps добавляются отсутствующие файлы; существующие сохраняются. Это также означает, что старые примеры и аддон внутри старого примера не обновляются автоматически. Актуальный комплект находится в godot-addon; используйте установку в проект через редактор.

Ошибка блокировки не завершает чужие процессы: закройте редактор или Godot, использующий заменяемую библиотеку, и повторите запуск. При проблеме отката журнал сохраняется — не удаляйте .motif-update вручную. Контрольные суммы обнаруживают повреждение пакета; это не цифровая подпись издателя.

Локальная сборка с файлом .motif-pending-commit ждёт, пока её коммит войдёт в опубликованный релиз. До этого BAT сохраняет установленную версию, чтобы ранний релиз не убрал новые функции. Изменения следует сливать с сохранением истории коммитов.

Как проверяется

Rust-тесты проверяют отказ атомарной замены, сбой резервной записи, внешние правки и удаление исходника, десять версий истории и восстановление нескольких окон. packaging/windows/test-update.ps1 проверяет настоящий ZIP, сохранность пользовательских файлов, повреждённую загрузку, блокировку файла, откат и восстановление прерванного обновления. CI проверяет Windows и Linux; публикация Windows-сборки ждёт также проверки runtime в Godot.
